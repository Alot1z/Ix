# AGENTS.md — Ix (personal fork of ix-infrastructure/Ix)

Rules for any agent (AI or human) working in this repository.

## No attribution footers — ever

Commit messages, PR descriptions, issue bodies, and comments must never carry
tool/agent attribution. Do NOT include any of the following, in any casing
variation:

- `🤖 Generated with Codebuff` or `Generated with Codebuff 🤖`
- `Co-Authored-By: Codebuff <noreply@codebuff.com>`
- `Co-authored-by:`, `Co-Authored-By:`, `Generated by:`, `AI:` lines
- Any mention of the tool, agent, or model that produced the work

Commit messages are plain conventional-commit text: a summary line, a blank
line, then the body. No footer block, no attribution, no tool branding.

## GitHub write policy

- This is a personal fork of `ix-infrastructure/Ix`. Do not push to the
  upstream repository or to any unrelated repository.
- No GitHub writes (issues, PRs, labels, comments, reviews, merges, reactions,
  branch mutations) without explicit per-action user authorization.
- PR/issue comments, when authorized, are technical navigation indexes only:
  no narrative, no authorship language, no AI attribution.

## Verification before claims

- Before claiming a change is verified, run the repository's own checks
  (`npm run typecheck` from `ix-cli/`, `npm test`); if a check was not run, say so.
- Do not fabricate filenames, symbols, line numbers, commits, or
  relationships. If exact references cannot be verified, say so explicitly.

## Fork / upstream boundaries

**Remote policy (enforced):**

- `origin upstream` → https://github.com/ix-infrastructure/Ix.git (fetch only — NEVER push)
- `origin fork`    → https://github.com/Alot1z/Ix-remap.git (push target)

Push ONLY to `origin fork`. Do not push to origin upstream.

**Invariant — re-verify after every fork-main mutation:**

Alot1z/Ix-remap:main must be:
- 0 commits behind `upstream/main`
- Ahead only by: deliberate fork-local infrastructure, governance, state, or approved product history

Check via: https://github.com/ix-infrastructure/Ix/compare/main...Alot1z:Ix-remap:main

**Fork-local vs upstream-product separation:**

Files below are fork-local engineering infrastructure. They belong on
`Alot1z/Ix-remap/main` and MUST NOT appear in upstream product PR diffs
unless explicitly and intentionally the scope of that PR:

- `AGENTS.md`
- `knowledge.md`
- `.agents/` (entire directory)
- `planning/` (entire directory)
- Reusable prompts, skills, specialist role definitions, handoff state

Before updating any upstream contribution branch, inspect:
`git diff upstream/main...HEAD`
and confirm none of the above appear unless the PR intentionally includes them.

## Agent system usage

This repository contains a persistent fork-local agent system in `.agents/`.
The system provides reusable specialist role definitions and workflows for:

- forksyc archaeology and upstream triage
- MCP/architecture/security/PR/Git/security/context/test/docs review
- Ix-findings validation
- session closeout and handoff

Use these artifacts as defaults for recurring work. Override only when the
specific task genuinely requires deviation. Document deviations in
`planning/AI-ENGINEERING-STATE.md`.

## Source-of-truth discipline

When facts are uncertain:

1. Run the Ix CLI (`ix explain`, `ix search`, `ix callers`, `ix impact`) before answering codebase questions.
2. Check `knowledge.md` for live upstream state, branch ownership, and contribution history.
3. Use `gh` CLI for live GitHub state (issues, PRs, CI status) — never rely on a stale cached report.
4. Mark artifacts contaminated by unverified tool prompting as `state:unverified` until verified by a live source.

## Contribution discipline

- Do not create new upstream PRs unless explicitly authorized per-action.
- Do not append commits to merged PRs (#422, #423 are merged; do not touch their branches).
- Do not delete or force-push upstream/main — this is a fork, not a fork backup.
- If a new issue is found, record it in `planning/AI-ENGINEERING-STATE.md` and stop unless an existing open PR can legitimately address it.

## Testing

Run `npm test` (from `ix-cli/`) before claiming any test-affecting change is verified. Run `npm run typecheck` after non-trivial CLI edits. Use `ix map --silent` after structural code changes.
